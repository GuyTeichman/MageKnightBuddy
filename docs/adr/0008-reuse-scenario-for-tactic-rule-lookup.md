# Reuse `Scenario` for Tactic pick-order/removal lookup, without adding per-mode entries

Issue #179 needs the Dummy Player tab (Standard and Proxy Player modes; Volkare mode already has its own Scenario field) to look up two things per round: who picks a Tactic card first (Dummy/Volkare vs. the real player(s)), and whether/when a used Tactic card gets permanently removed from the game. A full sweep of every scenario's rulebook text (`docs/rules/*.md`, cross-checked against the PDFs directly) found this genuinely varies per scenario — four distinct removal shapes (every round, once, twice, never) plus one pick-order exception (Volkare's coop mode has players pick first, unlike every other coop scenario).

The base rulebook's "Conquest" family has five player-count faces: Full Conquest and Blitz Conquest (Competitive, no Dummy Player), Solo Conquest (Solo), and Full Cooperation and Blitz Cooperation (Cooperative) — the latter two have no `Scenario` entry today, since the existing `Scenario` sealed interface was scoped to "scenarios the Score Calculator can score," which is solo-only. In every scenario we checked, a scenario's "Blitz" variant (shorter length, faster start) never changes its Tactic pick-order or removal rule — only round count, starting Fame/Reputation, and dice/Unit counts. So Blitz Cooperation's Tactic rule is identical to Full Cooperation's, and Blitz Conquest's (if a solo/coop Tactic-relevant face existed) would be identical to Solo Conquest's/Full Cooperation's.

We chose **not** to add new `Scenario` entries for the coop-only faces (`FullCooperation`, `BlitzCooperation`) or for the Blitz/Full distinction generally. Instead, the existing `Scenario.SoloConquest` entry (displayName "Conquest") is reused as the identifier for the whole Conquest family regardless of player mode — the Dummy Player tab's new solo/coop toggle (orthogonal to `Scenario`) is what actually selects between Solo Conquest's and Full/Blitz Cooperation's Tactic rules, both looked up from the same `Scenario` value. `SoloConquest`'s doc comment, previously "this app is solo-only, so 'Solo' is redundant," no longer describes why the name is what it is — it's kept because "Conquest" is genuinely the scenario's name, not because solo is the app's only supported mode anymore.

The Score tab's dropdown continues to iterate `Scenario.entries` unfiltered — no filtering was introduced, since no new entries were added for it to filter out.

## Consequences

- Adding a Tactic-rule lookup table means keying off `(Scenario, isSolo)` pairs (a `Scenario` value already covers every player-mode face of that named scenario), not off a bespoke "which face of Conquest" value.
- A future scenario whose Blitz variant genuinely *does* change Tactic behavior would break this assumption and need its own `Scenario` entry or an explicit override — none does today, but this is the assumption to revisit if one ever does.
- Solo Blitz (Apocalypse Dragon rulebook, p.24 — a solo-only, shorter Conquest face, currently unrepresented anywhere in this app) is deliberately out of scope here; it gets its own `Scenario` entry (and rules doc) in a separate future PR, not as part of this decision.
- Volkare's Return/Quest keep their own existing `Scenario` entries and are excluded from this Tactic-rule lookup table entirely — Volkare mode's pick-order/removal rule is identical between the two and doesn't depend on `Scenario` at all, so it's handled as its own fixed rule, not a table lookup.
